# Mensagens de commit sob demanda

Use este formato quando o usuário pedir este padrão ou referenciar este documento.
Inspecione mudanças reais e staging existente. Não execute Git por gerar uma mensagem.

Formato: `<type>: <descrição em inglês no imperativo>.`

Tipos: `feat` para funcionalidades, `fix` para correções e `chore` para manutenção ou documentação.
Uma linha, sem escopo, corpo ou rodapé; prefira até aproximadamente 72 caracteres.
Não use emojis, travessões ou descrições vagas. A mensagem deve refletir a mudança, não uma intenção.

Exemplo: `chore: add shared engineering guidelines.`

Entregue a mensagem como texto copiável. Regras operacionais em [git-workflow.md](git-workflow.md).
